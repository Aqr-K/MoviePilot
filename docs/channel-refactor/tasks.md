# 消息渠道重构任务

设计入口：[总体设计](design.md)、[平台边界](platform-boundaries.md)、[SDK 与兼容台账](sdk-boundaries.md)。当前源码、PR 和验证记录以 [提交索引](pr-series.md) 和 [验收索引](validation.md) 为准。

- 共享连接资源、独立投递/交互策略、条件 revision 写入与凭据脱敏。
- 平台拥有身份、地址、协议认证、凭据约束、专属配置、诊断及分段格式；公共核心独立执行授权。
- 入站、管理员录入、账号关联及历史读取使用统一规范主体，拒绝群组冒充、别名冲突及跨连接/群组/线程混用。
- 订阅、下载、浏览器设备及后台任务使用稳定业务归属并在副作用前复核撤权。
- 公共服务负责规则、受众、发送时间、Outbox 冻结计划、确认进度和重试。
- SDK 认证入站绑定连接、provider、身份空间与解析 owner；生命周期及提交失败不隐式回环、不重复投递。
- 公共 SDK 维持版本化筛选门面，保留必要插件/API/配置/固定升级兼容，普通插件不能注入可信证明。
- 独立平台与全部内置共存，实际申请、审批、规则及拒绝链和可执行架构门禁。
- 各独立单元的测试、静态检查、源码树和提交顺序记录于索引；真实企业微信继续跳过。

各项实现状态与准确修订按索引核对，不以历史测试批次、旧大 PR 或当前手测实例替代本次拆分的验收。
