# 消息渠道重构计划

设计与当前调用链见 [design.md](design.md)、[platform-boundaries.md](platform-boundaries.md) 和 [sdk-boundaries.md](sdk-boundaries.md)。提交及验收顺序见 [PR 索引](pr-series.md)。

1. 先提供独立的资源/身份契约、无全局缓存的传输标识及备份兼容修复。
2. 以现有模块契约和注册机制划分平台事实、规范主体、资源服务、固定离线升级与授权仓储。
3. 为订阅、下载及浏览器设备建立稳定归属；冻结投递计划与分段确认进度，隔离交互会话与业务权限。
4. 装配明确 owner 的受信 SDK 接收器，逐平台切换客户端入口、实际投递与恢复路径，保留明确的公开兼容适配。
5. 接入审批回执 Outbox，并验证独立平台与全部内置平台共存、申请/审批/规则/拒绝、兼容与架构约束。
6. 同步 API、SDK、架构、源码与验收索引；各单元完成适用检查后提交独立分支。

依赖 PR 在 fork 中逐级审阅，待官方前置合入后按索引逐个移交。正式升级只使用固定离线算法；部署和手测实例切换是独立操作。本轮真实企业微信测试跳过，使用隔离配置与模拟外部协议。
