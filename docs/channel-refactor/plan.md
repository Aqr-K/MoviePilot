# 消息渠道重构计划

职责设计和调用链见 [design.md](design.md)、[platform-boundaries.md](platform-boundaries.md) 与 [sdk-boundaries.md](sdk-boundaries.md)；当前 14 个依赖 PR 的顺序及修订见 [pr-series.md](pr-series.md)。

1. 完成独立前置合同、传输标识和备份兼容；已合入的修复不重复提交。
2. 实现平台事实与扩展契约、revision 资源和固定离线升级，保留公共授权与仓储边界。
3. 隔离订阅、下载和浏览器设备的稳定归属；保存通知冻结计划与分段确认进度。
4. 实现可信 SDK 入站、交互作用域、浏览器投递、运行装配及业务 API，逐平台保留协议 owner。
5. 实现审批回执与 Outbox，并验证独立平台共存、公开兼容、实际申请/审批/规则/拒绝及架构约束。
6. 将零碎审查单元整合为 14 个相邻依赖组；每组保留原验收终点的完整源码树。文档与 SDK/架构验收同组提交。
7. 通过精确租约覆盖本次 fork 主题分支，核验新 PR 的 HEAD 和基线后，关闭被吸收 PR 并清理过期分支；同步源码与验收索引。

本次只调整提交拓扑、PR 分组和文档，产品、测试、锁文件、CI 与安全门槛不变。相同源码树的验收复用，文档合同单独验证。官方前置完成后再按组移交官方，不强推官方或默认分支。真实企业微信继续跳过，手测实例和发布独立执行。
